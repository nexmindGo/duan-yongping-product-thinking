# 段永平产品思维 Skill

> 一套面向 ChatGPT、Claude / Claude Code、Codex 等 AI Agent 的开源产品决策框架。

用“用户价值、差异化、聚焦、消费者导向创新、敢为天下后”等产品原则，帮助你判断：**产品该不该做、MVP 该砍什么、差异化够不够、价格应该怎么想、什么时候不该进场。**

本项目基于《雪球特别版——段永平投资问答录（商业逻辑篇）》第 4 节“产品、差异化与创新”整理，将其中与产品相关的观点转化为一套可以被 AI Agent 使用的产品决策框架。

核心内容采用 `SKILL.md + references/` 组织，不绑定单一 AI 平台。

**非官方社区项目。** 本项目与段永平、雪球、OPPO、vivo、Apple、步步高及其他相关个人或公司没有隶属、授权、赞助或背书关系。

## 它解决什么问题？

这个 Skill 不是“段永平语录机器人”，也不会模仿段永平本人说话。

它更像一套产品决策检查系统。

你可以用它回答：

- 这个产品到底该不该做？
- MVP 应该保留什么、砍掉什么？
- 这个功能是真正的差异化，还是只是“不一样”？
- 用户真的需要这个功能吗？
- AI 或新技术是真的改善体验，还是为了创新而创新？
- 产品是不是已经做得太复杂？
- 应该如何从用户价值和差异化出发思考定价？
- 市场已经很拥挤了，现在还值不值得进入？
- 竞争对手增加了一个功能，我应该跟进吗？
- 为什么功能越来越多，产品却没有变得更有竞争力？

默认会给出明确结论：

**做 / 缩 / 先验证 / 延后 / 停止**

而不是只做模糊的优缺点分析。

## 核心思想

当前版本只聚焦“产品、差异化与创新”，主要整理出以下产品原则。

### 1. 用户价值优先于技术炫技

用户最终购买的不是技术本身，而是一个真正有用、好用的产品。

技术应该服务产品，而不是成为产品存在的理由。

### 2. 好产品首先应该好用

产品应该让用户更容易获得价值。

如果用户需要花很多时间学习、理解、配置，才能获得最基本的价值，就应该重新审视产品本身。

### 3. 差异化不是“不同”

真正的差异化不是：

> 我的产品和别人不一样。

而是：

> 用户需要某个东西，但现有竞争对手没有充分满足。

差异化最终要落到**用户需求**上。

### 4. 一个真正重要的差异化，可能比十个普通功能更有价值

产品不需要在所有地方都比竞争对手强。

如果能够在一个用户真正关心的问题上明显做得更好，就可能形成有意义的竞争力。

### 5. 聚焦是一种产品能力

公司的资源永远有限。

产品越多、功能越多、方向越多，研发、设计、渠道、库存、管理和注意力就越容易被分散。

真正重要的问题不是：

> 还能增加什么？

而是：

> 什么可以不做？

### 6. 建立“不为清单（Stop Doing List）”

产品能力不仅体现在“决定做什么”。

同样体现在：

**明确决定什么不做。**

每增加一个功能，都意味着资源、复杂度、维护成本和机会成本。

### 7. 没有差异化，很容易走向价格竞争

如果用户无法明显感受到产品之间的区别，价格就会越来越重要。

强差异化能够降低用户单纯按照价格进行选择的概率。

### 8. 定价应该和用户获得的价值有关

价格不应该只是：

```text
竞争对手卖 10 美元
所以我卖 9 美元
```

更应该思考：

> 我的产品给谁创造了什么价值？

以及：

> 用户愿意拿其中多少价值来交换产品？

### 9. 创新必须以消费者为导向

创新不是为了证明自己更先进，也不是为了追热点。

判断一个创新是否值得做，更重要的问题是：

> 它有没有让用户获得更好的体验？

### 10. 最好的技术，往往让用户感觉不到技术本身

技术能力越强，不一定意味着产品界面要越复杂。

真正好的技术，往往隐藏在体验背后。

用户只需要感觉：

> 这个东西很好用。

### 11. 不盲目追求“第一个做”

“敢为天下后”不意味着盲目追求第一时间进入市场。

有时可以让市场先验证真实需求，再决定是否进入。

但前提是：

**后中争先。**

也就是进入之后，你必须有能力把产品做得更好。

如果没有能力做到更好，仅仅因为市场已经被验证就进入，并没有意义。

### 12. 长期产品能力比短期指标更重要

市场份额、排名、营销热度和短期增长都不是产品最终目标。

更重要的是持续创造用户喜欢、愿意使用、愿意推荐的产品。

完整原则见：

[`references/product-principles.md`](references/product-principles.md)

## 使用示例

### 示例一：判断一个产品要不要做

```text
用段永平产品思维评估这个产品：

产品：
一个自动收集 X 上 AI 产品信息的网站。

用户：
AI SaaS 独立开发者。

用户现在：
每天手动刷 X、Product Hunt、Reddit。

我的产品准备：
自动收集信息、AI 总结、趋势图、排行榜、收藏、团队协作。

请判断：
做 / 缩 / 先验证 / 延后 / 停止。

不要只分析优缺点。
```

### 示例二：砍 MVP

```text
我准备做一个 SaaS，第一版有 8 个功能。

请按这个框架帮我：

1. 找出用户真正需要解决的问题
2. 判断最核心的差异化
3. 只留下最重要的 1—2 个功能
4. 其他功能全部进入“不为清单”
5. 给出第一版 MVP 应该验证的核心假设
```

### 示例三：判断要不要跟进 AI

```text
我的竞争对手最近都增加了 AI 助手。

请用段永平产品思维判断：
我是否应该跟进？

重点判断：
AI 是否真正改善用户体验，
而不是因为 AI 很火就建议增加。
```

### 示例四：判断一个拥挤市场还能不能进入

```text
这个市场已经有很多成熟产品。

我发现其中一个用户需求仍然没有被很好满足。

请判断：

1. 这个需求是不是有效差异化
2. 是否值得进入
3. 我有没有“后中争先”的可能
4. 如果进入，最应该聚焦哪里
5. 什么情况下应该直接放弃
```

### 示例五：分析定价

```text
竞争对手每月收费 10 美元。

我原本计划定价 9 美元。

请不要简单按照竞品价格给建议。

请从：
用户价值、产品差异化、替代方案、价格敏感度

来判断我应该如何思考定价。
```

## 默认输出结构

使用这个 Skill / 产品决策框架分析产品时，默认输出包括：

1. **结论**
   - 做
   - 缩
   - 先验证
   - 延后
   - 停止
2. **用户真正需要什么**
3. **真正的差异化**
4. **聚焦与取舍**
5. **创新与技术**
6. **定价与价值**（仅在相关时分析）
7. **不为清单（Stop Doing List）**
8. **下一步**
9. **使用到的原则编号**

目标不是给出一篇看起来全面的产品分析，而是帮助你做决定。

## 为什么第一版只做“产品、差异化与创新”？

第一版刻意保持范围小。

目前只处理：

- 产品
- 用户价值
- 产品差异化
- 聚焦
- 产品质量
- 创新
- 技术与体验
- 定价
- 市场进入

暂时不把以下内容混入同一个框架：

- 投资
- 企业文化
- 完整商业模式
- 品牌
- 营销
- 公司估值

原因很简单：

**一个 Skill 如果什么都能回答，往往意味着它没有真正聚焦。**

未来如果有足够明确的来源和实际需求，可以分别扩展：

- 商业模式版
- 企业文化版
- 品牌与营销版
- 完整商业决策版
